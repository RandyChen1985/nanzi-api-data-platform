# dev.sh 前后台启动与环境配置设计

## 目标

让数据服务平台的 `dev.sh` 与 NanZi AI 智能体平台的开发启动体验一致：默认前台运行，支持 `-d`/`--daemon` 后台常驻，并在启动前自动准备前端依赖。

## 行为约定

- `./dev.sh` 默认在当前终端前台运行后端，保留 Uvicorn `--reload`，按 `Ctrl+C` 停止。
- `./dev.sh -d` 与 `./dev.sh --daemon` 后台启动后端，进程脱离当前终端，日志写入仓库根目录 `app.log`。
- 端口从仓库根目录 `.env` 的 `API_SERVICE_PORT` 读取；未配置时使用 `8000`。
- 端口值只接受 1–65535 的十进制整数；配置非法时在停止旧服务前失败并给出明确提示。
- 启动前清理旧的 `frontend/dist` 和 `app.log`，仅停止配置端口上的旧进程。
- `frontend/node_modules` 缺失，或记录的 `package.json` 校验值与当前值不一致时执行 `npm install`；安装成功后更新校验文件。
- 前端依赖准备完成后执行 `npm run build`，失败则不启动后端。
- Python 启动器优先选择 `venv/bin/python`，其次选择 `.venv/bin/python`，否则使用 `python3`。
- 未识别的命令行参数直接报错；`-d` 和 `--daemon` 可同时出现但只产生一次后台启动行为。

## 实现边界

只修改 `dev.sh` 及其使用说明和脚本级回归测试，不调整应用端口配置、前端构建配置或后端业务代码。`.env` 采用文本解析，不通过 `source` 执行其中内容，避免把配置文件中的命令当作 shell 代码运行。

## 验证

- 用测试脚本覆盖前台/后台参数解析、`.env` 端口读取与默认值、非法端口拒绝、依赖校验文件判断。
- 用 `bash -n dev.sh` 检查 shell 语法。
- 在已有依赖可用时运行 `./dev.sh -d`，确认脚本返回、端口监听和 `app.log` 生成；验证后只停止本次启动的服务。
- 前台模式至少通过 `timeout`/人工 `Ctrl+C` 检查其不会自动转为后台。
